# 管理员文件预览设计

## 目标

将文件管理页面的“查看”操作从元数据详情抽屉改为直接预览文件内容。管理员通过后端提供的临时预签名地址预览有权限访问的活动文件，同时保留现有列表、筛选、分页和删除能力。

## 后端契约

后端已提供：

- `GET /api/admin/files/{fileId}/presigned-url`
- 权限：`file:download`
- 返回：`{ fileId, url, expiresIn }`
- 仅为 `ACTIVE` 文件生成预签名地址

前端不复用普通用户的 `/api/files/{fileId}/presigned-url`，避免管理员访问其他用户文件时触发所有权校验。

## 前端 API 与数据流

在 `src/types/file.ts` 增加预签名地址响应类型，在 `src/api/files.ts` 增加管理员预签名地址请求方法。现有列表查询和删除 API 保持不变。

点击文件行的“查看”按钮后：

1. 保存当前行文件元数据并打开预览弹窗；
2. 调用管理员预签名地址接口，显示加载状态；
3. 成功后根据文件的 `contentType` 渲染临时地址；
4. 关闭弹窗时清理当前 URL、文件状态和错误状态；
5. 使用请求序号保证旧请求不会覆盖后来打开的文件。

预签名 URL 只保存在页面运行时状态，不写入文件元数据或持久化存储。

## 权限

文件管理路由和列表仍要求 `file:read`。预览按钮仅在当前账号具有 `file:download` 权限时显示；删除按钮继续独立使用 `file:delete` 权限。前端权限控制只负责隐藏无效操作，后端仍执行最终授权校验。

## 预览交互

使用 Element Plus 弹窗替代当前文件详情抽屉：

- 图片（`image/*`）：使用 `img` 展示，保持原始比例并限制在弹窗可视区域内；
- PDF（`application/pdf`）：使用内嵌浏览器文档区域展示；
- 纯文本（`text/plain`）：使用浏览器文档区域展示；
- Word/Docx：浏览器无法稳定原生渲染时显示暂不支持在线预览，并提供在新窗口打开临时地址的入口；
- 其他类型：显示不支持在线预览，并保留在新窗口打开入口。

弹窗标题显示原始文件名，预览区域提供加载状态。临时地址请求失败时显示统一 API 错误消息和重试按钮。文件不是 `ACTIVE` 状态时不发起预览请求并提示当前状态不可预览。预览内容加载失败时显示失败提示，并保留在新窗口打开入口（若已获得地址）。

## 测试与验证

新增或调整测试以覆盖：

- 管理员预签名地址 API 的请求路径和响应调用；
- `file:download` 权限下点击查看并请求正确文件 ID；
- 无 `file:download` 权限时隐藏查看按钮；
- 图片、PDF、文本和不支持类型的预览分支；
- 预览请求失败、重试、关闭后重新打开及旧请求结果隔离；
- 现有列表加载、筛选、分页、删除和错误处理行为不回归。

使用 Node 20.20.2 执行 `npm run test`、`npm run type-check` 和 `npm run build`。
