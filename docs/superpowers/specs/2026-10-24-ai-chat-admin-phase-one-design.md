# AI Chat 管理后台第一阶段设计规格

## 1. 范围与目标

第一阶段采用可联调的垂直切片，打通管理后台从登录到运营概览的主链路：

- 登录、刷新恢复、当前会话退出、全部会话退出。
- 动态 Token Header 与当前用户权限上下文。
- 后台主框架、权限过滤、路由守卫和无权限页。
- 运营概览的日期筛选、核心指标、趋势图和 AI 调用成功率。
- Node 20.20.2 下的类型检查、自动化测试、生产构建和浏览器验收。

本阶段不实现用户、角色、权限、供应商、模型、用户分析、会话分析和 Token 分析页面，也不新增后端接口。

## 2. 技术和工程约束

- 使用 Vue 3、TypeScript、Vite。
- 引入 Vue Router、Pinia、Element Plus、Axios、ECharts 和 Vitest。
- `package.json` 的 Node 引擎约束调整为兼容 Node 20，并以 Node 20.20.2 作为验证版本。
- Axios 默认基础地址为 `/api`；Vite 开发代理将 `/api` 转发到 `http://localhost:8080`。部署时可通过 `VITE_API_BASE_URL` 配置后端地址。
- 桌面端优先，1280px 及以上完整展示；窄屏折叠侧栏，内容区域保持可读。
- 不引入配置驱动 CRUD、低代码引擎或与本阶段无关的通用抽象。

## 3. 视觉与页面结构

沿用已确认的“清爽运营台”视觉基线：

- 深蓝固定侧栏、浅灰蓝内容背景、白色卡片。
- 蓝紫色为主色，绿色表示成功，橙色表示提醒，红色表示失败或危险操作。
- 顶栏只展示页面上下文、帮助入口和当前账号菜单。
- 卡片、表格、抽屉和弹窗使用统一的紧凑间距与 8px 圆角。
- 不使用大面积渐变、玻璃拟态或装饰性动画。

页面包括：

- `/login`：用户名、密码、密码显隐、回车提交、提交加载态和后端错误提示。
- `/dashboard`：页面标题、最近 30 个自然日筛选、四张指标卡、平台使用趋势、AI 调用成功率和局部错误/空状态。
- `/forbidden`：独立的无权限说明页面，并提供返回可访问页面的入口。
- `AdminLayout`：侧栏导航、顶栏、账号菜单、内容插槽和窄屏侧栏折叠。

侧栏只显示当前用户有入口权限的菜单项。第一阶段实际只展示运营概览，但布局为后续系统管理、AI 配置和数据分析菜单预留分组结构。

## 5. 认证和路由数据流

1. 登录调用 `POST /api/auth/login`。
2. 成功后保存响应中的动态 `tokenName` 与 `tokenValue`，再调用 `GET /api/auth/me` 获取完整权限上下文。
3. Axios 请求拦截器读取认证 Store，以 `tokenName` 作为请求头名称，以 `tokenValue` 作为请求头值；不写死 `satoken`。
4. 刷新页面时先恢复本地 Token，再调用 `/api/auth/me`。认证初始化期间路由等待初始化完成。
5. 根路径根据当前用户权限跳转到第一个可访问页面；第一阶段通常为 `/dashboard`。
6. 未登录访问后台页面跳转 `/login`，并保留原目标地址。
7. 已登录访问 `/login` 时跳转首个可访问页面。
8. 已登录但没有任何后台入口权限时进入 `/forbidden`。
9. 已登录用户访问无权限路由时进入 `/forbidden`，不清理认证态。
10. `/api/auth/logout` 或 `/api/auth/logout-all` 完成后清理本地认证态并回到登录页。

路由元数据声明入口权限，菜单、路由和后续按钮统一使用同一权限判断函数；后端权限校验仍是最终安全边界。

## 6. API 客户端和错误处理

统一响应结构为：

```ts
interface ApiResponse<T> {
  success: boolean
  code: string
  message: string
  data: T
}
```

成功请求在 API 层解包为 `data`，业务页面不感知响应包装。失败请求抛出包含 HTTP 状态、业务码和后端消息的统一错误对象。

处理规则：

- `401`：清理认证 Store 和本地 Token，跳转登录页。
- `403`：保留当前认证上下文，展示无权限提示或进入无权限页。
- `400`：保留后端校验消息；登录表单在字段级校验失败时保留用户输入。
- `404`：展示资源不存在或刷新提示。
- `409`：展示后端冲突原因。
- `500/502`：展示通用失败提示，同时保留后端可读消息。
- 不做自动重试；重复提交由按钮加载态和表单锁定阻止。

## 7. 运营概览数据设计

概览页默认展示最近 30 个自然日，界面日期为闭区间 `[from, to]`，发给后端时转换为半开区间 `[from, to + 1 day)`。日期转换集中在 `utils/date.ts`，使用本地日期运算，避免时区导致少算结束日。

概览和趋势请求并行执行：

- `GET /api/admin/dashboard/overview?from=...&to=...`
- `GET /api/admin/dashboard/trend?from=...&to=...`

两类请求独立保存加载、成功数据、空状态和错误状态。一个接口失败时，另一个接口已经成功的内容继续展示；局部区域提供重试入口。日期快捷项和自定义日期在确认后触发请求，不在每次输入时请求。

概览指标展示：

- 总用户。
- 会话总量。
- AI 调用。
- Token 消耗。
- AI 调用成功数、失败数和成功率。

趋势图支持后端返回的日期序列。第一阶段默认展示活跃用户和新会话两条线；其余后端趋势字段保留在类型定义中，后续阶段再开放切换。图例与数据字段保持一一对应。ECharts 实例在组件卸载时销毁，避免重复初始化和内存泄漏。

## 8. 验证策略

增加 `test` 脚本，使用 Vitest 覆盖以下稳定逻辑：

- API 响应成功解包和错误对象生成。
- 动态 Token Header 的生成，不假设 Header 名称为 `satoken`。
- 401 清理认证状态、403 保留认证状态的分支。
- 认证初始化和首个可访问路由选择。
- 角色码、权限码判断。
- 默认 30 天日期范围。
- 闭区间日期转换为后端半开区间。
- 365 天最大跨度校验。

类型检查使用 `npm run type-check`，生产构建使用 `npm run build`，全部在 Node 20.20.2 下执行。

浏览器验收包括：

1. 登录成功进入运营概览。
2. 刷新后通过 `/api/auth/me` 恢复用户和权限。
3. 已登录访问登录页自动跳转。
4. 无概览权限进入无权限页，侧栏不显示无权限菜单。
5. 退出当前会话和退出全部会话。
6. 日期快捷项、自定义范围和非法范围反馈。
7. 概览接口或趋势接口单独失败时的局部错误状态。
8. 1280px 以上布局、窄屏侧栏折叠和无整体横向滚动。
9. 浏览器控制台无阻断使用的错误。

## 9. 后续阶段衔接

第一阶段完成后沿用以下基础设施继续扩展，不改变认证、API 解包、权限判断和日期转换边界：

1. 系统管理：用户、角色、权限及关联分配。
2. AI 配置：供应商和模型。
3. 数据分析：用户、会话和 Token。

本阶段不为这些页面创建假数据交互，也不提前实现无法持久化的操作。
