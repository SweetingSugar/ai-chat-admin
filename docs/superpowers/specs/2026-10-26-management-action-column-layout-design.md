# 管理页面操作列同行布局设计

## 1. 背景与目标

权限管理和模型管理页面的表格操作列固定为 `150px`。在当前 Element Plus 按钮默认间距下，“编辑”和“删除”无法在单元格内同时容纳，因而换行显示。本次调整让两个操作按钮在每条记录中保持同一行，同时保留现有交互和窄屏可用性。

## 2. 范围与方案

采用“增宽操作列”方案：

- `src/views/system/PermissionManagementView.vue` 的操作列宽度由 `150px` 调整为 `180px`。
- `src/views/ai/ModelManagementView.vue` 的操作列宽度由 `150px` 调整为 `180px`。
- 保留现有 Element Plus 按钮、权限判断、测试选择器、编辑事件、删除确认和删除事件，不增加新的布局抽象或业务逻辑。
- 保留两个页面已有的表格横向滚动机制。窗口较窄时横向滚动整张表，而不是压缩或换行操作按钮。
- 供应商、用户和角色页面不在本次范围内，它们已有足够的操作列宽度。

## 3. 交互与数据流

布局调整不改变数据流：列表加载、权限控制、编辑抽屉、删除确认和成功后刷新均保持现状。仅改变操作列的静态宽度，使两个同行按钮拥有足够的可用空间。

## 4. 测试与验收

补充两个页面的组件回归断言，验证操作列宽度为 `180px`，并确保编辑、删除按钮仍按现有权限渲染。验证步骤如下：

1. 运行权限管理和模型管理页面的组件测试。
2. 在 Node 20.20.2 下运行 `npm run test`。
3. 运行 `npm run type-check` 和 `npm run build`。
4. 启动前端，在权限管理和模型管理页面确认每行“编辑”和“删除”处于同一行。
5. 缩小窗口后确认表格可以横向滚动，操作列不会再次换行。

## 5. 非目标

本次不改变表格其他列宽、不调整按钮视觉样式、不修改其他管理页面、不引入共享操作列组件，也不修改任何 API 或权限逻辑。
