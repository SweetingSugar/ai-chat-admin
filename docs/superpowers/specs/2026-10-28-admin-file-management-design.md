# 管理员文件管理设计

## 目标

在现有 AI Chat 管理后台中增加管理员文件管理页面，对接后端新增的文件查询、详情和删除接口。页面应沿用当前管理页面的视觉和交互模式，并根据权限控制入口和删除操作。

## 实现范围

- 在“系统管理”分组新增“文件管理”入口，路径为 `/system/files`。
- 新增文件类型定义和 API 封装：
  - `GET /api/admin/files`
  - `GET /api/admin/files/{fileId}`
  - `DELETE /api/admin/files/{fileId}`
- 新增文件管理页面，使用服务端分页和服务端筛选。
- 新增文件详情抽屉。
- 新增按 `file:delete` 权限控制的删除操作和二次确认。
- 增加 API、页面、路由和导航测试。

## 页面结构

文件管理页面位于 `src/views/system/FileManagementView.vue`，复用现有 `PageHeader`、管理面板、Element Plus 表格、状态标签和错误提示样式。

筛选区域包含：

- 原始文件名文本输入
- 用户 ID 数字输入
- 文件类型文本输入
- 文件状态下拉框：全部、`ACTIVE`、`DELETING`、`DELETE_FAILED`、`DELETED`
- 创建日期范围，格式为 `yyyy-MM-dd`
- 查询和重置操作

点击查询或重置时回到第 1 页并请求列表。列表请求只发送非空筛选值，日期始终按后端要求的 `yyyy-MM-dd` 格式传输。

表格显示文件名、用户 ID、文件类型、格式化文件大小、状态、创建时间、更新时间和操作列。文件名过长时截断显示，并通过提示保留完整内容。分页使用后端 `PageResult` 的 `total`、`current` 和 `size`，每页可选 20、50、100 条。

## 数据流与权限

`src/api/files.ts` 提供类型化的列表、详情和删除方法。列表方法接收 `page`、`size`、`userId`、`originalName`、`contentType`、`status`、`createdFrom` 和 `createdTo`，通过 `apiClient` 的 `params` 配置发送查询参数。

页面使用 `useAuthStore` 判断权限：

- 路由和导航入口要求 `file:read`。
- 具备 `file:read` 但没有 `file:delete` 时仍可查看列表和详情，但不显示删除按钮。
- 删除按钮点击后使用现有 `ElMessageBox.confirm` 确认；确认期间防止重复提交。
- 删除成功后重新请求当前列表以同步总数和后端状态；删除失败时保留当前列表并显示 API 错误。

点击“查看”时调用详情接口并打开抽屉。抽屉展示文件 ID、原始名称、所属用户、内容类型、文件大小、状态、创建时间和更新时间。详情加载失败只影响抽屉，并提供重试，不影响列表。

## 错误处理

列表加载失败时保留筛选条件，显示页内错误和重试按钮。详情加载失败显示抽屉内错误。API 客户端统一转换的错误消息直接用于提示，不在页面重复解析 HTTP 状态。空列表显示现有空状态文案。

本次不增加上传、下载、预览或批量删除，避免扩大后端新增查询与删除接口的范围。

## 测试与验证

- API 测试验证列表查询参数、详情路径和删除方法。
- 页面测试验证首次加载、完整筛选参数、分页切换、查询/重置回到第 1 页、详情抽屉、删除确认、删除权限隐藏和错误重试。
- 路由与侧边栏测试验证 `file:read` 权限下的入口和无权限访问保护。
- 使用 Node 20.20.2 运行 `npm run test`、`npm run type-check` 和 `npm run build`。
