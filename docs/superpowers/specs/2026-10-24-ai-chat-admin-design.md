# AI Chat 管理后台设计规格

## 1. 目标

基于现有 AI Chat 后端接口构建可实际使用的管理后台，覆盖平台概览、用户与 RBAC 管理、AI 供应商与模型配置，以及用户、会话和 Token 聚合分析。

首期严格使用现有统计口径，不提供管理员查看逐条会话内容或逐条 AI 调用日志的能力。为保证 RBAC 分配和前端权限控制可正确工作，后端仅补充当前用户权限、用户角色关联和角色权限关联的读取数据。

## 2. 技术约束

- Vue 3、TypeScript、Vite。
- Vue Router 负责路由，Pinia 负责认证上下文，Element Plus 提供后台组件，Axios 负责 HTTP，ECharts 负责统计图表。
- 依赖与构建必须兼容 Node 20.20.2。
- 桌面优先，主要面向 1280px 及以上宽度；窄屏折叠侧栏，复杂表格允许横向滚动。
- 后端默认地址为 `http://localhost:8080`，前端通过 Vite 环境变量和开发代理配置基础地址。
- 不引入配置驱动 CRUD、低代码引擎或与首期功能无关的抽象。

## 3. 视觉系统

采用已确认的“清爽运营台”方案：

- 深蓝色固定侧栏，浅灰蓝内容背景，白色卡片。
- 主强调色为克制的蓝紫色；绿色表示正常和成功，橙色表示提醒，红色表示失败或危险操作。
- 顶栏保持轻量，仅展示页面上下文、帮助入口和当前账号菜单。
- 数据卡片强调数值与变化信息，图表保持低装饰、清晰图例和统一 Tooltip。
- 表格、筛选栏、抽屉和弹窗遵循统一的 8px 圆角与紧凑间距。
- 不使用大面积渐变、玻璃拟态或装饰性动画。

## 4. 信息架构

### 4.1 路由

| 路由 | 页面 | 入口权限 |
| --- | --- | --- |
| `/login` | 登录 | 匿名 |
| `/dashboard` | 运营概览 | `admin:dashboard:read` |
| `/system/users` | 用户管理 | `system:user:read` |
| `/system/roles` | 角色管理 | `system:role:read` |
| `/system/permissions` | 权限管理 | `system:permission:read` |
| `/ai/providers` | 供应商管理 | `ai:provider:read` |
| `/ai/models` | 模型管理 | `ai:model:read` |
| `/analytics/users` | 用户分析 | `admin:statistics:user:read` |
| `/analytics/chat` | 会话分析 | `admin:statistics:chat:read` |
| `/analytics/tokens` | Token 分析 | `admin:statistics:token:read` |

登录后访问根路径时，进入第一个有权限的页面；通常为运营概览。没有任何后台读取权限时展示独立的无权限页面。

### 4.2 导航分组

- 工作台：运营概览。
- 系统管理：用户管理、角色管理、权限管理。
- AI 配置：供应商管理、模型管理。
- 数据分析：用户分析、会话分析、Token 分析。
- 个人菜单：当前账号摘要、修改密码、退出当前会话、退出全部会话。

菜单项按当前用户的权限码动态显示。路由守卫和操作按钮使用同一权限判断；后端权限校验仍是最终安全边界。

## 5. 页面设计

### 5.1 登录

- 用户名与密码表单，支持回车提交和密码显隐。
- 登录成功后保存后端返回的动态 `tokenName` 与 `tokenValue`，请求 `/api/auth/me` 获取完整权限上下文，再进入首个可访问页面。
- 已登录用户访问登录页时直接进入后台。
- 登录失败展示后端业务消息，不区分用户名不存在与密码错误以外的额外细节。

### 5.2 运营概览

默认查询最近 30 个自然日，提供日期范围快捷项和自定义范围。

内容层级：

1. 总用户、会话总量、AI 调用、Token 消耗四张核心指标卡。
2. 平台使用趋势图，支持查看新用户、活跃用户、新会话、消息、AI 调用和 Token。
3. AI 调用成功率环图及成功、失败调用数。
4. 输入与输出 Token 构成、用户启停状态摘要。
5. 依据权限展示的快捷入口。

概览和趋势接口并行请求。任一接口失败时仅对应区域进入错误状态，其他已成功内容继续显示。

### 5.3 用户管理

- 后端返回完整用户数组，页面提供本地关键词和状态筛选。
- 表格展示账号、昵称、联系方式、状态、最后登录时间和创建时间。
- 详情编辑仅允许修改昵称、邮箱、手机号和头像。
- 状态开关调用独立启停接口，提交期间锁定当前行。
- 分配角色时先读取用户详情中的 `roleIds`，在角色列表中正确回显；保存为全量替换。
- 编辑、启停和分配角色按钮分别按对应权限码显示。

### 5.4 角色管理

- 列表展示角色名称、代码、描述、排序、状态和更新时间。
- 支持新增、编辑和删除；删除前二次确认，冲突时显示后端返回原因。
- 权限分配使用层级树，先读取角色详情中的 `permissionIds`，保存为全量替换。
- 表单中角色代码使用等宽样式，便于识别稳定标识。

### 5.5 权限管理

- 根据 `parentId` 将权限数组构造成树形表格。
- 展示名称、权限码、类型、路由、组件、排序和状态。
- 支持新增根权限、新增子权限、编辑和删除。
- 当前迁移数据均使用 `permissionType: 3`，页面将其显示为“接口权限”；其他未定义类型显示为“类型 N”。编辑表单保留数字字段并提示当前接口权限使用值 `3`，不臆造后端尚未定义的类型语义。
- 删除前二次确认；有关联角色时直接展示后端冲突消息。

### 5.6 AI 供应商管理

- 卡片摘要与表格组合展示供应商类型、地址、超时、状态、凭证配置状态和版本。
- 新增时 API Key 必填；编辑时留空表示保留原密钥。
- API Key 永不回显，`hasApiKey` 仅转换为“已配置/未配置”状态。
- 删除前二次确认；仍有关联模型时展示冲突原因。

### 5.7 模型管理

- 支持按供应商、启用状态和默认模型筛选。
- 表格展示模型名称与代码、供应商、上下文窗口、最大输出 Token、采样参数、流式支持、默认状态和启用状态。
- 新增和编辑表单覆盖后端全部可配置字段及其合法范围。
- 设置默认模型前提示该操作会清除其他模型的默认标记。
- 启用模型失败时展示供应商未启用等后端业务原因。

### 5.8 用户分析

- 指标卡：总用户、启用、禁用、新增、活跃。
- 趋势图同时展示新增用户和活跃用户。
- 日期范围与后端最大 365 天约束一致。

### 5.9 会话分析

- 指标卡：总会话、新会话、总消息、生成任务和生成成功率。
- 趋势图支持切换消息、用户/助手消息、生成任务及失败状态。
- 状态摘要展示完成、失败和中断数量。
- 首期不展示会话列表、消息正文或单次生成详情。

### 5.10 Token 分析

- 汇总指标：调用、成功、失败、取消、输入 Token、输出 Token、总 Token、估算 Token 和平均耗时。
- 分组可切换 `DAY`、`MODEL`、`PROVIDER`、`USER`。
- 分组结果用表格与横向条形图呈现。
- 后端不返回总条数或总页数，因此只提供上一页/下一页；当前结果少于 `size` 时禁用下一页，不展示虚构的总页数。

## 6. 前端架构

```text
src/
  api/            认证、系统、AI、统计请求与类型
  assets/         全局样式和设计令牌
  components/     确实复用的业务组件
  layouts/        后台主框架
  router/         路由表和权限守卫
  stores/         认证上下文
  utils/          日期、数字、权限与响应处理
  views/          按菜单划分的页面
```

### 6.1 状态边界

- Pinia 仅持有 Token、当前用户、角色码、权限码和认证初始化状态。
- 页面列表、筛选、弹窗与提交状态留在页面组件内，不进入全局 Store。
- 路由元数据声明入口权限，统一权限函数控制菜单、路由和按钮。

### 6.2 API 客户端

- 请求拦截器读取动态 Token 名称和值并设置 Header。
- 响应层解包统一 `ApiResponse<T>`，业务层只接触 `data`。
- 401 清除认证状态并跳转登录页。
- 403 保留当前上下文并展示无权限提示；路由级无权限进入专用页面。
- 400 显示表单或参数错误，404 显示资源不存在，409 显示冲突原因，500/502 显示通用失败提示并保留后端可读消息。
- 重复提交通过按钮加载状态和表单锁定避免，不做自动重试。

### 6.3 日期语义

界面对用户展示闭区间日期。发给后端时保留开始日期，并将用户选择的结束日期加一天，转换成后端要求的 `[from,to)` 区间。所有统计页面共用这一转换，避免指标少算最后一天。

## 7. 后端补充

### 7.1 当前用户权限上下文

`GET /api/auth/me` 返回现有用户字段，并增加：

```json
{
  "roleCodes": ["admin"],
  "permissionCodes": ["admin:dashboard:read", "system:user:read"]
}
```

登录响应继续返回 Token 和基础用户对象；前端保存 Token 后主动请求 `/api/auth/me`。

### 7.2 用户角色回显

`GET /api/system/users/{id}` 的详情响应在现有用户字段基础上增加：

```json
{
  "roleIds": [1, 2]
}
```

列表接口不增加该字段，避免为每行查询关联关系。

### 7.3 角色权限回显

`GET /api/system/roles/{id}` 的详情响应在现有角色字段基础上增加：

```json
{
  "permissionIds": [1, 2, 3]
}
```

列表接口不增加该字段。写入接口继续保持全量替换语义。

## 8. 加载、空状态与反馈

- 首次加载使用骨架屏；局部刷新保留已有数据并显示轻量加载状态。
- 空列表提供与当前权限匹配的操作入口；无创建权限时仅说明暂无数据。
- 表单校验同时覆盖后端规定的必填、长度、数值和枚举范围。
- 删除、清空关联、设置默认模型、禁用账号和退出全部会话均要求明确确认。
- 成功操作使用短提示，并在成功响应后刷新受影响数据。
- 日期或筛选改变不会在每次输入时立即请求，使用确认或短防抖触发。

## 9. 测试与验收

### 9.1 自动验证

- API 响应解包、动态 Token Header、错误分支。
- 认证初始化、401 清理、首个可访问路由选择。
- 路由与按钮权限判断。
- 统计日期闭区间到后端半开区间的转换。
- 权限树构造和角色/权限回显。
- Token 下一页可用性判断。
- TypeScript 类型检查和生产构建。

### 9.2 浏览器验收

- 登录、刷新恢复、退出和会话失效。
- 侧栏权限过滤、直接访问无权限路由和按钮权限。
- 用户编辑、启停与角色分配。
- 角色 CRUD、权限树回显与全量保存。
- 权限 CRUD。
- 供应商与模型 CRUD，包括 API Key 留空和默认模型确认。
- 首页和三类分析页的日期筛选、加载、空数据与错误状态。
- 1280px 以上完整布局以及窄屏侧栏折叠和表格横向滚动。

## 10. 非目标

- 管理员查看全部会话、消息正文或 AI 调用日志明细。
- 聊天客户端与 SSE 对话功能。
- 手机端专用表格和表单布局。
- 用户注册、用户创建、密码重置或头像上传。
- 国际化、主题切换、服务端菜单配置和低代码页面生成。

## 11. 完成标准

- 所有已定义路由和操作与后端权限码一致。
- 页面可完成后端当前支持的管理操作，不提供无法持久化的假交互。
- 后端补充字段能安全回显角色与权限关联。
- 统计日期和指标口径与后端文档一致。
- Node 20.20.2 下安装、类型检查、测试和构建通过。
- 浏览器主流程验证通过，且没有阻断使用的控制台错误。
