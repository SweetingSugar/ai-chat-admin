# 管理页面操作列同行布局 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the “编辑” and “删除” actions render on one row in the permission and model management tables without changing their behavior.

**Architecture:** Keep both pages’ existing Element Plus table columns and action buttons. Increase only the fixed-right operation column width from `150px` to `180px`; the existing table overflow containers continue to handle narrow viewports. Add component-level regression assertions for the rendered operation-column width, then verify the visual result in the running app.

**Tech Stack:** Vue 3, TypeScript, Element Plus, Vue Test Utils, Vitest, Vite.

---

### Task 1: Add failing layout regression tests

**Files:**
- Modify: `src/views/system/__tests__/PermissionManagementView.spec.ts:55-84`
- Modify: `src/views/ai/__tests__/ModelManagementView.spec.ts:71-137`

- [ ] **Step 1: Add the permission-page failing assertion**

Append this test inside the existing `describe('PermissionManagementView', ...)` block:

```ts
  it('keeps edit and delete actions in a wide operation column', async () => {
    const wrapper = mount(PermissionManagementView, { global: { plugins: [ElementPlus] } })
    await flushPromises()

    const actionHeaders = wrapper.findAll('.el-table__fixed-right th')
    expect(actionHeaders.some((header) => (
      header.text() === '操作' && header.attributes('style')?.includes('width: 180px')
    ))).toBe(true)
  })
```

- [ ] **Step 2: Add the model-page failing assertion**

Append this test inside the existing `describe('ModelManagementView', ...)` block:

```ts
  it('keeps edit and delete actions in a wide operation column', async () => {
    const wrapper = mount(ModelManagementView, { global: { plugins: [ElementPlus] } })
    await flushPromises()

    const actionHeaders = wrapper.findAll('.el-table__fixed-right th')
    expect(actionHeaders.some((header) => (
      header.text() === '操作' && header.attributes('style')?.includes('width: 180px')
    ))).toBe(true)
  })
```

The selector targets the fixed-right header generated by Element Plus because both operation columns use `fixed="right"`. The tests intentionally expect `180px` before the view code is changed.
